# LOOM 个人测试版

这是 Windows x64 个人开发测试包。它使用独立数据目录，当前仍按测试版交付。

## 安装和打开

从浏览器下载 ZIP 后，先右键 ZIP → **属性** → 确认信任来源并勾选 **解除阻止** → 应用，再完整解压。若没有“解除阻止”，直接解压即可。随后双击 **Install-Loom.cmd**。安装完成后，从 `%LOCALAPPDATA%\Programs\LOOM-Personal` 双击 **Start-Loom.cmd**。保持窗口开启，服务就绪后打开同目录的 **Open-Loom.url**。

第一次启动时，窗口会显示登录用的 Token，把它填入登录页。账号连接入口是左侧 **连接与设备**（或右上 **连接与设置**）→ 选择运行端 → **连接设置**。常见 API 凭据可填入通用环境变量；原生 OAuth 登录或自定义模型配置文件仍按对应 CLI 的方式设置。请勿公开分享 Token 或 API 密钥。

个人数据保存在 `%LOCALAPPDATA%\LOOM\personal-preview-20261116`，重启和升级继续使用这个目录。程序和数据分开保存，安装包里不包含你的账号或对话。默认地址是 `http://127.0.0.1:64852/`。

暂时不想安装，也可以直接双击解压目录里的 **Start-Loom.cmd**。两种入口共用同一份预览数据，同一时间只打开一个。停止时，在启动窗口按 **Ctrl+C**。

## 升级和切回上一版

先在原启动窗口按 **Ctrl+C** 停止，再解压新包并双击新包里的 **Install-Loom.cmd**。安装器会检查包内文件，保留上一版程序，完成后仍从固定安装目录打开 **Start-Loom.cmd**。检查失败时，当前版本不变。

要切回上一版，先停止 LOOM，再双击安装目录的 **Rollback-Loom.cmd**。它保留个人数据，不撤销已完成的任务。新版已经运行过时，仅在两版数据格式相同时允许自动切回；格式不同或旧包没有格式信息，会保留现状并说明原因。

本地无下载标记的安装、启动与重启已经实测通过。带 Internet 下载标记的未签名 PowerShell 脚本在 RemoteSigned 策略下会被拦截，因此浏览器下载后的首次使用需要上面的信任步骤；若电脑受组织签名策略管理，应使用经组织认可的签名包。启动器不会自动解除阻止或修改执行策略。

安装和升级不需要管理员权限，不修改全局 PATH、开机自启或其他正在运行的程序。安装器不会删除旧版本或个人数据。

### 自定义位置

在包目录的 PowerShell 中运行：

```powershell
.\Manage-Loom.ps1 -Action Install -InstallDirectory 'D:\Apps\LOOM' -DataDirectory 'D:\LOOM-Data' -Port 64852
```

首次安装可选择路径和端口，后续升级沿用这些设置。数据目录应使用一个尚不存在的独立目录，由 LOOM 创建访问权限；不要手动创建或复制日常数据库进去。

## 包内内容与权限

包内包括同一源码构建的 Host、Server、Core 与 CLI、生产 Web 界面、项目管理的 Skill 资源，以及带独立 Node 运行时和第三方许可证说明的 Pi 0.85.1。启动器只对本次进程显式选择随包 Pi；四种运行时的配置目录另放在预览数据根的 `runtime-home` 下，不复制现有账号凭据。

标签图标和品牌标记使用已选定的 LOOM 图片，个人助手头像保持独立。Pi 新增 `workspace_read_write` 显式选项，只允许在 Core 选定工作目录内执行原生 read/write/edit；受控模式不开放 shell、MCP、未知工具或任意文件系统访问。这是可信本地主机中的工具权限边界，不是对同一操作系统账号下其他进程的强隔离承诺。

另外的 `workspace_workflow` 是显式选择的受限工作流模式：在文件工具之外，只接入既有的八类 LOOM 业务操作，继续经过 Core 身份、授权、Claim/Fence 和幂等校验，不借此开放任意 shell。它不改变已有只读、读写或 native 模式的默认选择。

## 电脑查看与控制

带有 `computerRuntime` 清单字段的包包括独立 Python 3.14.10、Pillow 13.0.0 和现有电脑工具，许可证与文件哈希一并保留。安装后的启动和解压直接启动都使用包内运行环境，无须在系统里另装 Python。

打开“电脑”，先允许查看屏幕，需要输入时再点“接管电脑”。手动控制最长五分钟；离开页面、按 Esc 或点“归还控制”会停止。给助手的权限需要单独确认，截图会发送给该助手使用的模型。当前支持的助手运行方式为 Codex、Claude 和 DSH；Pi 的助手电脑工具仍需显式启用，保持原有边界。

## 可选 Pi Purge 扩展

带有 `optionalPiPurgeVersion` 清单字段的新候选会在 `runtime/extensions/pi-purge/` 内附带固定 v0.3.0 的原始源码、许可证、闭包清单，以及 LOOM 受管适配器。已有旧候选可能没有此目录，以实际清单为准。

**默认关闭，不是启动器自动注入。** 当前受管适配支持 Off/Append：先核对独立的 Run/Bot/epoch、Persona 文件摘要与原版扩展摘要，再在原生会话重置后激活，保留原宿主提示词。助手界面和 Core 已接通 Persona 的 Off/Append，已有 UI 34/34、真实 Core Append/Off 和运行中冻结隔离证据。同一次从空白界面配置 Persona 到真实模型完成任务的整段验收仍待补齐。

CI 只跑无模型回归和交付包闭包检查，不含账号配置、Persona 正文或用户会话，不自动把本地的真实模型测试结论签给另一个构建。

## 验证证据与尚未完成的部分

`candidate-manifest.json` 记录源码提交和包内文件哈希。`e3-manifest.json` 记录同一源码的干净 Windows 构建与隔离集成测试结果。E3 使用真实 Pi 进程、正式界面和自动化鼠标输入，但模型响应来自受控的本地测试服务；它不是真实模型验收，也不是用户亲自作出的 Owner 验收。

真实模型执行、完整的四 Runtime × 四能力矩阵、独立设备恢复，以及正式发行资格仍是单独的验收项。打包过程不会写入用户验收结论，不复制凭据，不晋升正式版本，也不迁移日常数据。

项目已经另行完成正式 UI 发起的真实 Lead／双 Worker／返工审查闭环，以及本地模型使用远端 DevicePort 的运行中重连验证；这些记录不能自动替代本包的商用模型验证。当前明确的限制是：DSH 的显式模型路由、Rule 和 MCP 已有真实证据；最新 `dsh-diagnostic-03` 还验证了原生 read 读取 Core 冻结的选中 Skill，并验证反选后不进入新 Run。DSH 原生 Skill 注册表是否加载该技能仍未证明，Hook 尚无已验证传输。Windows Claude 保持原有发现与执行准入边界。不要把界面中的“已选择”或进程启动成功当作这几项能力已经可用。

使用前应核对包内的源码提交与文件清单；尚未通过的项目不因“测试包”名称而被视为完成，用户最终接受始终留给本人。
