## 一、这个项目在做什么

LOOM = 以 Rovai 为 UI 与运行时底座的产品分支。Rovai 本身已有对话、团队、使命、执行、Diff；
LOOM 要补的是 ACCP 那套控制层（Task/DAG/依赖/Attempt/候选/证据/验收）与 archify 流程视图。

架构四层（旁路 UI 以 Rovai 为基础扩展；控制层职责沿用旧 `orchestrate.py` 但实现参考 Rovai/ACCP；
执行层可替换，`pi-skill` 只是其中一种 Pi 能力）。全文见 `docs/loom/control-plane.md`。

## 三、明确没做到（不要当成已完成）

1. **Review / 人工验收 / 依赖首次释放冻结**：完全没做。`artifact_accepted` 依赖边目前**永远不释放**——这是诚实的未实现，不是 bug。
2. **证据核验（Verification）**：没有。候选只有 `UNVERIFIED/PENDING` 初值，没有核验方法与结论记录。
3. **UI 未接真实 Core**：编排 tab 读的是 fixture mock（`scripts/fixtures/loom-workspace`、`mission-board`）。已证明"生产组件在真数据形状下正确渲染"，未证明"UI→Core→Runtime 全链路"。
4. **archify 流程图仍是顺序卡片**：有节点、负责人、阻塞原因、依赖名称，但**没有连线拓扑**。
5. **品牌未替换**：还是 Rovai 视觉。
6. **候选"不可修改"只是内容冻结**：触发器冻结内容列，判定列（`acceptance_status`）仍可被直接 UPDATE。结论防篡改要靠下一片的授权 Review 记录，不能只信这一列。
7. **无执行器闭环**：`claim.acquire` 只写认领事实，**不启动任何 Runtime**。

## 四、风险与坑（会咬人的）

1. **迁移链脆弱点**：每加一号迁移，前一步结尾的 `Current` 断言必须同步放宽为
   `Current | SupportedMigrationSource(schema==N)`，否则**整条链建库全炸、所有测试失败**。
   219 和 220 都踩过这个坑（`db_loom.rs` 里 `migrate_acceptance_criteria_version` / `migrate_claim_lease`）。
   再加 222 时，221 也要同样处理。
2. **迁移号 ≠ schema 号**：迁移 218↔168、219↔169、220↔170、221↔171（`migration = schema + 50`）。别搞混。
3. **bero 机器 3 个环境失败**：`database_admission` 的 3 条报 `IdentityChanged{stage:Revalidation}`，
   固定基线 `33f6ded` 同样复现，是本机文件系统语义问题，不是回归。**不能写成全绿**。
4. **上游无历史**：本仓库是 Rovai 单提交快照（当初 shallow 无法 push，重建了干净历史）。
   `git fetch upstream` 只能用来比对，不能正常 merge。
5. **工兵不自带编译**：pi 工兵无 shell，`ok:true`/自报完成一律不算验证。**主管必须自己编译并跑测试**——
   这一轮工兵交活 7 次，其中 4 次有编译错误或测试全红。
6. **不要碰日常 userData**：Core 测试一律临时目录 + 隔离；验收进程禁止指向日常 Electron userData。

## 8. A 线：2.2 终审结果（同日已闭环）

Astra（`oct-response/gpt-6-astra`，只读）复审结论：**先 BLOCK，修完后 PASS（建议 APPROVE）**。

**它挖出的 P2**：`claim_acquire` 仍是**锁前取时**（`loom.rs:1112–1118` 在 `transaction_with_behavior(Immediate)` 之前）。后果是双向的：
- 等锁跨过旧租约过期点 → 把还活着的租约误判为过期（误报拒，方向安全）
- 等锁耗时超过租期 → 签发一张**出生就已过期**的 claim（方向不安全：下一个提交者立刻能接管）

**修法**（`d360194`，主管亲改，只动这一处）：把取时移到拿到写锁之后。`task_release` 未改——Astra 判定可接受，因为它的锁前时间只写 `updated_at`，不参与租约或状态判断。

**复验**：bero `cargo test -p rovai-core --lib loom` → **32 passed / 0 failed**；全量 `--lib` → **464 passed / 3 failed**，三个失败全是 `database_admission` 的 `IdentityChanged{stage:Revalidation}`（与基线 `33f6ded` 同一批，属机器环境，不得算绿也不得算回归）。Astra 复审 PASS。

**残余风险（诚实记账）**：这个 P2 没有确定性回归测试。要写的话得把取时函数做成可注入，再用 SQLite busy 回调确认「正在等锁」，推进假时钟跨过期点后放锁，断言接管成功且新租期从推进后的时刻起算。目前直接调 `Utc::now()`（`loom.rs:1118`），所以这段只能靠代码评审守，不能靠测试守。

**过程教训**：`gpt-6-astra` 一次吃「五问审计 + 完整 A1 计划」时 30 分钟零输出，必须 abort；收窄成「只审四问、1200 字内」后 10 分钟内出 PASS/BLOCK。以后给 Astra 的单一任务别超过一个切片。
