## 架构决定

- UI 继续独立 `loom-native` Mikka/PiBot 组件树，所有新增界面由主管实现；不恢复旧业务页面或旧 CSS。
- Core 为唯一任务、Run、候选、审查、用户验收和能力选择真源。Pi 是受管可插拔运行端，不成为第二个工作调度/事实数据库。
- 发现程序、检测原生配置、用户绑定、安装/账号就绪、实际运行是独立事实。只读发现不能自动执行本地 Hook、发送模型请求或复制秘密值。
- 四类资源保留原生来源/版本、优先级与支持矩阵；LOOM 定义、原生只读发现、用户选择和实际装载分层。
- 原生/内置 Pi 分开；封包需固定依赖、SHA、许可与自有运行根，不覆盖用户 Pi。模型认证和收费不被“内置”掩盖。
- ACP = Agent Client Protocol 扩展接口，版本/能力协商；不把当前原生协议全部冒充 ACP。不采用未经核实的“ACP v2 都已支持”说法。ACCP 参考项目与业务验收理念另表，不混缩写。
- Computer 为显式启用的 Provider：先授权看屏，再授权控制；浏览器会话身份＋设备＋控制租约＋TTL＋顺序；断线/过期/归还后拒绝输入。捕获失败不得生成假屏幕。只操作用户授权桌面，不给任意命令执行接口。
- 本机/云端通过现有 Host/Node 边界连接；云端能力在执行节点当地发现。不能用本机路径或已有 SSH 工具冒充产品已经配对的 Node。
- 流程图和资产图投影真实依赖/版本/证据，点击可读对应工作或成果；图上的操作必须走版本化 Core 命令。
- 平台内部协作 Skills 不混入用户工作技能列表，内部安全/路由工具保留但不暴露为难懂的可勾选项。
