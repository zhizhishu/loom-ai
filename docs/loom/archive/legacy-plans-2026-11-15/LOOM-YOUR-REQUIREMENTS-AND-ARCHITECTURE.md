---

## 1. 一句话

> **LOOM = 一个永远在的 Bot ＋ 可换的大脑 ＋ 可连的多台电脑 ＋ 统一的能力/记忆/授权。**

不是"四个 CLI 的统一外壳"，是一个**搬家也不会丢的助手**：
今天 Windows、明天 Mac 或手机、后天大脑搬到 Linux 云服务器——
**Bot 还是那个 Bot，聊天、记忆、任务、成果一样不丢**。

## 2. 你已经拍板的 9 条（产品边界，不许工兵乱改）

| # | 需求 | 具体是什么 |
|---|---|---|
| 1 | **UI 不推倒** | loom-native 左中右三栏、配色、助手、群聊、工作/资产/流程/电脑四标签全保留。后端随便换，前端不重绘。品牌锁定你上传的**粉发绿眼黑猫耳**那张图 |
| 2 | **Core 可以大重构** | 旧 Mission / AgentRun / RPC / Schema 不是长期合同，可以推翻重写。但**已有用户数据、资产、密钥、在跑的服务必须能迁移能回滚** |
| 3 | **只支持 4 个运行端** | Claude Code / Codex / DSH / Pi。封闭首期。ACP 是协议不是第五个，ACCP 是参考不是第五个 |
| 4 | **Pi 优先，DSH 可插拔** | Pi 做受管内置包（已跑通），DSH 做同级候选。同样的任务同样的权限实测比过，才准换默认 |
| 5 | **四能力一处勾选** | Skill / MCP / Rule / Hook。**勾选 ≠ 加载 ≠ 真调用**，必须有运行端回执。记忆是独立第五层 |
| 6 | **长期 Bot + 多 Agent** | Bot 永久存在、能进群、有主助手（Lead 只是协调角色，不是管理员）、能把活拆给别的 Bot 并各自验收 |
| 7 | **电脑和大脑分开** | B、C 电脑**可以只装小 daemon**（文件/终端/浏览器/鼠标键盘），不强制装 Pi/DSH；重活才选装本地 Runner |
| 8 | **证据式验收** | 不粘贴受限许可源码；工兵不许自报完成；Root 独立复跑才算过 |
| 9 | **人格/记忆跨内核** | 换大脑不该让 Bot 失忆，也不该让所有电脑重新配对。人格不能借机扩权 |

## 3. 架构图（文档 §B 原图）

```
            你（Web / 桌面 / 以后手机）
                    ↓
        ┌───── 现有 LOOM UI（三栏，不动）─────┐
                    ↓
     身份 / 工作区 / 以后租户 ── 授权·策略·审计
                    ↓
   ┌──────────────────────────────────────────┐
   │  BotIdentity ─ BotMemory ─ BotTeam ─ 群聊路由 │   ← Bot 层（永久）
   │  人格绑定 / Prompt 合成 / 记忆范围             │
   └──────────────────────────────────────────┘
                    ↓   群聊只唤醒该醒的人
   ┌──────────────────────────────────────────┐
   │  Goal → Step DAG → Assignment / 租约 / 围栏   │   ← 任务层（ACCP 式）
   └──────────────────────────────────────────┘
                    ↕
   ┌──────────────────────────────────────────┐
   │  Coordinator：事件落库 → 唤醒 → 等你处理/审查   │   ← 调度层（可恢复）
   └──────────────────────────────────────────┘
                    ↓
  ┌─ RuntimePort ──┐ ┌─ DevicePort ─┐ ┌─ 能力注册表 ─┐
  │ Pi    受管内置 │ │ 纯设备模式     │ │ Skill       │
  │ DSH   可选内置 │ │ 文件 / 终端    │ │ MCP         │
  │ Codex 原生     │ │ 浏览器 / 电脑  │ │ Rule        │
  │ Claude 原生    │ │ 可选本地Runner │ │ Hook        │
  └────────────────┘ └──────────────┘ │ Memory      │
                    ↘        ↙         └─────────────┘
          不可变的 证据 / 成果 / 人工审查
```

**关键：三条竖线彼此独立。**
换大脑（Runtime）不影响电脑（Device），换电脑不影响 Bot，
Bot 换人格不自动获得新权限。

## 4. 六个不能混的词（混了就是实现错了）

```
账号 / 工作区
  ├── Bot            ← 永久身份、有记忆、有配置。你能长期找到他
  ├── BotTeam        ← 成员名册 + 协作策略（不是把四个进程硬拉进一个会话）
  ├── 群聊            ← 你说话的地方，不是任务的真源头
  ├── Goal           ← 你的一个长期请求
  │    └── Step      ← 拆出来的步骤，有依赖关系（DAG）
  │         └── Assignment   ← 这步归谁，带租约防抢
  │              └── RunAttempt      ← 一次具体推理/执行
  │                   └── DeviceInvocation ← 一次电脑操作（可以没有模型！）
  ├── AttentionItem  ← 需要你拍板的事
  └── Artifact       ← 真文件 + 来源 + 你的审查结论
```

| 容易混的 | 真相 |
|---|---|
| Bot = 进程？ | ❌ Bot 永久，进程随时死 |
| 群聊记录 = 任务？ | ❌ 聊天里说"你去做 X"，必须落成 Step/Assignment 才算数 |
| Lead = 管理员？ | ❌ Lead 只是本群协调者，不自动拿到别人的文件和密钥 |
| 模型说完成 = 完成？ | ❌ 先变成 candidate，你 Review 过才 accept |
| 跑完 Run = 你接受了？ | ❌ 两回事 |
| 电脑操作必须有模型？ | ❌ DeviceInvocation 可以单独成立，B 电脑不用装 Pi |

## 5. 四个运行端的边界

| 运行端 | 定位 | 怎么装 | 当前真实状态 |
|---|---|---|---|
| **Pi** | 第一优先，受管内置 | LOOM 自带固定版 Node+Pi+启动器 | ✅ 唯一真跑通的（RPC、扩展、双 Bot 隔离都验过） |
| **DSH** | 第二优先，可插拔 | 固定 Host + Profile，可选装、隔离 | ⬜ 还没公平实测 |
| **Codex** | 原生适配 | 不封包，探测你机器上已装的 | ⬜ 未测 |
| **Claude Code** | 原生适配 | 不封包，**Win11 本机明确禁用执行**，只做配置发现 | ⬜ 按设计不跑 |

## 6. 四能力的生命周期（为什么"勾了≠能用"）

```
发现 → 查看 → 勾选 → 配置 → 冻结 → 物化 → 已加载 → 真调用 → 有证据
                 ↑你在 UI 做的只到这              ↑这三步必须运行端回执
```
`不支持` / `失败` / `已撤销` 也是正常状态，必须显示出来，不许藏。

Claude 的配置可以**只读扫描当参考**，但把 Claude 的 Hook 原样复制给 Pi **不会生效**，
更不许自动执行陌生 Hook。

## 7. 权限：三档 + 四层

你对「某台电脑的某个项目」可以选：

| 档位 | 行为 |
|---|---|
| **Never** | 不来烦你，做不了就直接拒绝 |
| **Ask** | 要新文件夹/写入/终端/鼠标时，明确告诉你「**哪个 Bot** 要在 **哪台电脑** 做 **什么**」，你点批准 |
| **Full** | 在**指定设备 + 指定目录 + 指定时限**内少问 |

四层独立执行，少一层都不算数：
`用户策略` → `资源授权` → `运行端沙箱` → `操作系统真拦截`

> "选工作目录"只是告诉 Bot 从哪开始，**不等于给了全盘权限**。
> 真正的拒绝要 Core 和那台电脑本机一起落实，不能只写一句"不要越界"的提示词。

## 9. 我可能理解偏的地方（你直接改）

1. **"搬到 Linux 云端"是最终目标还是选项？** 文档里是 P13，排在很后面。如果你其实想**早点**把大脑放云上，顺序要调。
2. **手机端**只在愿景里出现过一句，没有任何设计。你要不要它进首期？
3. **多用户/企业**（P14）我按"明确不做"处理的——单用户先稳。对吗？
4. **Pi Purge / 人格系统**占了相当篇幅，但它是 Pi 独有的可选插件。你是把它当**核心卖点**，还是**可有可无的实验**？
5. **"4–6 周可用版"的"可用"**——我理解成：你能在 UI 建 Bot、拉群、给目标、自动派两个工兵、其中一台只装 daemon 的 Windows 完成文件操作、你 Review 后拿到能打开的文件。**这个定义对吗？**
