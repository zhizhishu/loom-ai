### 推荐首屏信息架构（用户视角，非代码接口定义）

```text
顶部：全局搜索｜当前项目/主机｜待我处理｜连接状态
左窄栏：对话｜工作｜助手｜连接与设备              [设置在底部]
次侧栏：随左栏显示最近聊天/群聊、项目、工作清单或助手名册
中央：真正的聊天 + 任务卡/成果卡/执行事件 + 底部输入框
右侧统一工作 Dock：
    [工作] [资产] [流程] [电脑]       搜索/过滤/展开/隐藏
    └当前会话、项目或任务关联内容；任务详情/文档/画面在此展开
点击头像：当前助手资料/能力侧卡，或者跳「管理助手」，不再复制整个右栏
```

左窄栏仍保留当前 64px 的轻量视觉、动态头像和用户认可的整体秩序；图标的精确增删属于待确认的细节，**不是删掉整个左栏**。窗口材料保留磨砂/轻分层，但降低空白、减弱重复边线；不在每张卡片上叠模糊。右侧的统一 Dock 应复用现成 `WorkMap.tsx` / `FactGraph.tsx`（真实依赖、候选版本、文件关系、选择节点、缩放）与 `ComputerPanel.tsx`（观看/人工输入租约），只重组内容入口与状态同步，不另造一套图数据库或电脑工具。状态优先于装饰。

## 三、助手创建：用户希望的一条流程

1. **是谁**：昵称、动态头像、职责（一行）、沟通方式（可选）；不暴露旧大段 charter。
2. **用谁干活**：选择 Claude / Codex / DSH / 内置或本机 Pi；卡片同时展示已发现/已认证/模型数量/失效原因。不能把“已发现”当“可运行”。
3. **给什么能力**：四个标签 `Skills / MCP / Rules / Hooks`，自动汇集当前 Host 已允许的原生来源和 LOOM 能力库，另提供「从目录/连接导入」。用户在同一流程内阅读来源、风险、兼容范围、勾选。MCP 缺认证显示连接引导；Hook 高风险需正文/范围单独确认；不复制日常客户端密钥。
4. **在哪里干**：选择本机/已配对节点、项目目录/工作区与“仅一次/本会话/持久授权（仅原生支持时）”相应可选项。权限有 scope、目标、可撤回期限；不提供假的“始终允许”。
5. **预览并创建**：总结 AssistantDefinition revision、Runtime、Node、工作区、4类能力计数、待就绪项。先创建/保存，再按是否实际可启动决定「开始聊天/加入群聊/先完善设置」。失败保留草稿与 commandId，避免重复创建。

**能力状态真源**：`found`(Host观察到) → `reviewed/imported`(入库) → `selected`(分配到助手) → `frozen`(进入本次 Run) → `applied`(执行端确认载入) → `invoked`(实际调用回执)。不得把“已选”标成“可用”。当前用户主要缺的是第1至第3步的无缝入口，以及第4/第5步跨端证据。

## 六、必须守住的安全与产品不变量

- Core 仍是唯一真实任务/Run/候选/审查/用户接受权威；Pi/其他CLI不维护第二任务数据库。
- 资源发现只读；真实执行时使用冻结身份/摘要和目标节点能力回执；不把本机路径当作云节点路径。
- Skill ≠ 提权；MCP凭据不会自动迁移；Rules ≠ OS权限；Hooks要预览正文/范围且按 Runtime 支持度审查。
- 用户看屏、人工接管、Agent自主电脑工具是三类授权；未过安全回归继续关闭 Agent桥。
- 没有用户确认的“始终允许”范围不写入持久授权，不把 allow_session 伪装成整机永久信任。
- 正常 UI 只说“助手、能力、聊天、工作、资产、电脑”；诊断层才出现 RPC、Lease、Digest、Adapter 等术语。
- 原用户实例与独立验收实例、Windows本机与Bero云测试、模拟和真实模型执行都要分清，没通过就不标通过。
