## 1. 这次确实做到了什么

### 1.1 内置 Pi 不再只有方案

Windows 受管包位于项目 `resources/runtime/pi/`，包括原生 `pi.exe`、随包 Node、固定 Pi 版本、完整嵌套依赖与文件哈希清单；不依赖用户先安装全局 Pi 才能运行这个包。

本轮验证版本为 Pi 0.85.1 / Node 24.14.1。6682 个文件逐一通过完整性检查，实际调用包内 launcher 的版本命令及隔离 JSONL `get_state` 都成功。最终 launcher 另有两项 Windows 原生测试，并拒绝用混合 `--mode rpc --version` 参数绕过独立配置根要求。

此外，用**这个随包 launcher**、用户批准的默认 DeepSeek 工兵模型，实际读取了一个随机验收文件并正确返回内容。随机值不在提示词中，不能靠复述指令通过。模型认证值只经子进程环境提供，没有复制用户原生账号文件、修改原 Pi 模型配置或写明文密钥到交付文件。

**边界**：这证明内置 Pi 引擎→真实模型→读工具可用；该次验收由 Pi 工兵入口驱动，不能替代 LOOM 群聊→Core→模型→成果的完整端到端验收。目前新 Core 的 Pi 可用性读回还显示模型目录为空，UI 直启模型链仍是下一阶段阻塞项。

### 1.2 四端原生环境不再只靠静态按钮

“连接与设置”已经读取真实 Host：Claude、Codex、DSH、Pi 四个程序都被发现；Pi 的安装来源实际指向项目内置包。检测路径、检查状态、版本与模型目录分别显示，不把 PATH 找到程序冒充已登录或可执行。

“客户端能力”在实际新 Core 中读到了 74 条当前客户端声明的资源，按 Skills/MCP/Rules/Hooks 分类，保留来源和兼容限制。普通浏览不导入、不启用、不执行 Hook。MCP 导入有版本检查，默认停用且未分配；账号与原生配置不自动复制。

这是当前主机上的发现结果，不是每台电脑固定都有 74 项。所有端的账号、模型、权限和能力实际装载矩阵尚未全部跑完。

### 1.3 创建工作已经和普通群聊分开

“开始新对话”中新增“共同完成工作”：填写名称与目标、选成员和主助手、选工作区域。它调用真实 `missions.create` 并通过 `missions.get` 读回对应工作，而不是只造一个空聊天。

默认不启动模型；只有显式勾选“创建后开始执行”才走开始命令。结果未知保持同一 commandId，创建后开始失败不重复造工作。实际验收已证明创建、打开、刷新后保留，以及未勾选时零派工。

### 1.4 电脑页现在是真画面、真操作

真实链路已经通过：浏览器产品 UI → 当前 Host 认证 → 原生屏幕捕获 → 用户单独确认接管 → 点击/文字输入 → 归还控制。

本轮在**自建、精确前台身份的 Windows 测试窗口**中证明了点击会改变按钮、输入会进入真实文本框、截图会回到 LOOM 电脑页。归还后使用旧 lease 再发输入，Host 返回 409，窗口没有受到新的输入。断开画面后才关闭测试窗口，未拿用户私人桌面当测试内容。

这项交付是**用户人工接管**。助手电脑工具的临时授权模块虽然已有代码和 UI，但安全回归仍存在失败，当前验收 Host 保持该桥接关闭，不能说 Agent 自主操作已经完成。

当前实例通过项目内前台 supervisor 保持运行，不是已安装的系统服务。可见 Chrome 使用单独验收 profile，通过正常登录表单进入；不会把 token 放在 URL、命令行或用户日常浏览器配置。运行/登录脚本和 token 仅留项目私有验收目录，不应打包对外。

## 4. 修过的真实问题与不要倒退的约束

1. 封包解析必须保留嵌套多版本依赖，根包从明确来源解析；manifest覆盖Node、entry和launcher，不能只比部分文件。
2. Windows Rust canonical路径带设备前缀，Node入口拒绝：只有完成包含关系校验后才规范化传给Node，不能删掉路径安全检查。
3. Pi 0.85 API Key配置采用 `$ENV`/`${ENV}` 解析，裸变量名会当作字面值。隔离验收只存环境变量引用，不复制账号值。
4. Pi MCP此前只在JS桩中可用但Core早分支没投影；已接到真实冻结投影和warm-host身份。JS校验的是完整文件字节含换行，Rust现在使用同一序列化/摘要函数。
5. HTTP MCP重定向曾被SDK沿用：现在显式拒绝，实际第二源请求计数为0；不得为接通工具退回自动重定向。
6. Windows文字输入必须发送UTF-16单元的按下/抬起成对事件，重复字和非BMP字符不可省略。
7. 本轮新业务Core可在旁路明确隔离启动；不因旧服务环境缺失就猜HOME或覆盖用户旧数据库。
