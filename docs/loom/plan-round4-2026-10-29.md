第三轮 392c139、a442620 两次 Actions 红，都是「Run Rust format and compile checks」步 rustfmt 差异（loom.rs:3168/6794/6803），bero 只跑了测试没跑 fmt。从本轮起，任何 push 前主助手在 bero 同一 commit 上必须顺序跑完并贴退出码：

`

任一非 0 不许 push。缺这三条证据就 push 的，即使 Actions 恰好绿也记一次流程违规。

### 审计（Astra xhigh 只读）抓出的真问题，全部已修

1. **P1 C2 可伪通过**：第一版按 token 比对触发器体，原语句加一个 `WHEN 0` 就仍能通过而永不触发；`WHEN 0` / `RAISE(...) WHERE 0` / 注释凑 token 都能绕过。改成整条触发器语句归一化后**全等**比较（迁移与校验共用同一份文本）。
2. **P1 部分唯一索引可过**：`CREATE UNIQUE INDEX ... (plan_id, relative_path) WHERE 0` 名字、列、unique 标志全对，但一行都不约束。补 `partial=0` 要求。
3. **P2 测试缝是全局 Mutex**：并行测试会让一个用例偷走另一个用例的回调，且安装后提前失败会残留回调。改成 `thread_local`。
4. **P2 错误码混淆重试与重修**：证据读不到（路径被拒 / 文件消失）原先报 `LOOM_EVIDENCE_HASH_MISMATCH`，与「字节真的不同」共用一个码。新增 `LOOM_EVIDENCE_UNREADABLE`，两种情形从此可分。
5. **P2 读句柄不是快照**：读取期间被追加/截断会记下一个没人真正看过的长度。读完后与句柄 `metadata().len()` 对账，不一致即拒。
6. **P2 投影测试不能排除「读时重算」**：原测试登记后没动文件。补「登记后改写文件，投影仍报记录的 digest/size」。
7. **P3 索引测试注释写错**：把「只对 plan_id 唯一」误说成"放行同 plan 重复路径"，实际是过度限制。改为「删掉索引」与「partial 索引」两个真反例。
8. **P3 契约注释**：`sizeBytes` 注明「登记时算出的字节数，不是现在磁盘上的大小」。
