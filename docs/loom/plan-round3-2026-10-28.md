## 1. 角色与编组

| 角色 | 载体 | 模型 | 权限 | 职责 |
|---|---|---|---|---|
| 主助手（盯盘） | 另一个 Agent 主线程 | 当前会话模型 | 全权，但只做判断 | 派工、合并、在 bero 独立复跑、按验收书判 PASS/FAIL、approve |
| 审计手 Astra-x | pi-skill | oct-response/gpt-6-astra，思考档 xhigh | --tools file 只读 | 出切片方案、列风险、终审 diff；≤1200 字输入，第一行 PASS/BLOCK |
| 工兵 Flash-x | pi-skill | oct-chat/deepseek-v4.1-flash | file,write 或 file,shell（二选一，不并开） | 1–3 个文件有界实现，或在 bero 跑命令贴原始输出 |

一组 = 1 Astra + 1 Flash。 固定流程：Astra 出方案 → 主助手审过 → Flash 实现/跑命令 → 主助手 bero 复跑 → Astra 终审 → 主助手 approve。

同一时刻最多 3 个写入组并行，且写入文件白名单互不重叠（只读 / 只跑命令的组不计数，如阶段 A 的 G1）。冻结文件（loom.rs / db_loom.rs / db.rs / loom.ts）同一时刻只许一组碰，且该组 Astra 审计期间谁都不许改。

## 2. 沙箱与远端分工

- 编译 / 测试一律 bero（berobox skill，komari-ssh run --host bero），工作区 /root/sandbox/projects/loom，export PATH="$HOME/.cargo/bin:$PATH"。
- 自己的项目用默认 runc 容器或宿主 cargo；**不加 --runtime=runsc**（慢约 70%）。只有第三方脚本、来路不明的代码才走 gVisor。
- UI 夹具在 bero 必须 xvfb-run；真 Core 测试前必须 cargo build -p rovai-core --bin rovai-core（别用 pnpm core:build:debug）。
- 长任务用 result --job <id> 查；submission_unknown 不许自动重发。
- **GitHub（zhizhishu/loom-ai）：G4 组新增 CI workflow，让 push 后 Actions 在干净 Ubuntu 上再编一次、测一次，当作 bero 之外的第二证人。用户已于 2026-10-28 17:19 CST 一次性授权 bero 沙箱与自有仓库 zhizhishu/loom-ai 的一切活动（push、建分支、跑 Actions、清理 bero 进程/容器），无需逐次点头；每次 push 仍要在 TASK.md 记 commit 与 Actions 链接**。上游 murray17/rovai-ai 仍只读，不在授权范围内。
- skill-cli 仓库禁止 git add -A；loom 仓库提交只 add 白名单文件。
- 本机改动怎么到 bero：主助手只 add 白名单文件、commit 后 push 到 zhizhishu/loom-ai，bero 上 git pull（bero 与 Actions 测同一个 commit）；临时试跑也可 scp/rsync 白名单文件或让 Flash 直接在 bero 工作区改；复跑前在 bero 上 git status + git diff --stat 确认只多了白名单文件，并记下 base commit。
