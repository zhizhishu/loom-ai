## 五、为什么做这么久

时间主要花在「闭环验证与纠错」，不是画页面：

1. 不能破坏 Rovai 底座：每加一号迁移都要动 db.rs 十余处注册点，并放宽上一步终态断言，否则整条建库链全红（219 / 220 / 221 / 222 都踩过）。
2. UI 状态必须等于 Core 生命周期：Rust 冻结规则和 TS 求值器必须逐条等价，否则存储说「放行」、线协议说「阻塞」。
3. 评审 / 核验 / 候选三者不可伪造、不可改写：每张表三个触发器，还要覆盖 INSERT OR REPLACE、直删等绕过路径。
4. 依赖边只能在正确时机冻结一次，且「谁后到谁放行」。
5. 审计要冻结快照：一次边审边改被 Astra 判 STUCK；大任务一次给 Astra 曾 30 分钟零输出。
6. 纠错成本：工兵交活 7 次中 4 次编译错误或测试全红；主管两次给错规格（task_done 带 review_id、泳道宽 180/48 装不下）；旧二进制跑新测试假绿；bero 缺中文字体导致截图方块字；改错夹具文件。
